KETS cTrader account isolation

- Each cTrader connection is stored against the signed-in KETS user ID.
- OAuth state is signed and time-limited, binding the callback to the KETS user who started authorization.
- KETS fails closed if it cannot enumerate the accounts granted by cTrader.
- A dedicated ctrader_account_owners table reserves each cTrader account ID for one KETS user. The reservation and connection save occur in one database transaction.
- A cTrader account already reserved by another KETS user is rejected. Disconnect releases that user's reservations.
- The website warns users to check the cTrader ID in the browser before approving authorization.

Important limitation:
cTrader's authorization screen is hosted by cTrader, and this application does not receive a separately verified human identity for the cTrader ID from the account-list response. Therefore KETS can enforce account-ID isolation, but cannot independently prove that two different account IDs belong to different human cTrader identities. Users must sign into their own cTrader ID before authorizing. Test with two separate KETS users and separate cTrader IDs before production deployment.
